# Publication and data scope

The public project is **K-Farm : Smart Harvest**, in `raykjh/k-farm-smart-harvest`. Original project source is licensed under [Apache License 2.0](../LICENSE). The public scope was approved on 2026-10-11. The software is an operational MVP and policy proposal, not a field-certified service or an adopted public program.

## Included

- Application, constraint engine and AI decision-validation source.
- Database schema, initialization and isolated verification tools.
- Synthetic people, resource and geometry fixtures used by automated tests.
- Locked dependency references, environment placeholders, setup instructions and a bounded verification summary.

The functional engine is included; this is not an interface-only demonstration. Dependencies are installed from their package registries and retain their own licenses. Original source licensing does not relicense maps, manufacturer assets, government datasets, personal records or trademarks.

## Excluded

Actual environment files and API keys, operating databases and backups, authentication and recovery material, personal information, cached provider snapshots, raw model requests and responses, screenshots and recordings, and internal historical handoffs are not distributed. Synthetic contact fields are test inputs, not authorized destinations for messages.

Three provider-derived samples are obtained separately: the registered-parcel reference, the four-center cadastral sample and the capacity-study input. Their absence disables only the corresponding reference or study source; it must not fabricate cadastral evidence or reset operating records. The former fixed-date sample installer is retired even when its parcel reference is present. New fictional applicants must use the ordinary registration/planning/work-result paths, with explicit synthetic provenance. See [optional data setup](clean-installation.md#optional-provider-data). Live KMA and VWorld access requires the installer's own authorization and credentials.

Provider API access does not itself settle redistribution rights. A source citation or Apache-2.0 license on this code does not grant permission to publish a provider's raw response. A displayed boundary does not verify the applicant's ownership, consent or eligibility.

## Security and runtime boundaries

The prepared source was checked for configured secrets, known private contacts and common private-key/token patterns. The current JavaScript dependency audit reported no known advisories. Neither check is a security certification, and both need repeating as code and dependencies change.

Development database credentials and loopback addresses are for local setup only. A public server needs a separate synthetic database, unique credentials, HTTPS, role-scoped accounts, rate limits, backup/restore checks and a reviewed shared inference budget. A published source repository does not expose the development PC or authorize a public deployment.

No actual carrier SMS, machine command or physical equipment loan was performed in the reported checks. Notification receipts are local records. Field use requires agronomic validation, appropriate agreements, privacy and legal review, safe equipment integration and responsible personnel.

Keep vulnerabilities and sensitive samples out of public issues. If a credential is exposed, revoke or rotate it; removing a file does not erase existing clones or historical copies.

[Verification results](verification.md) distinguish model-free reproduction from real-model decisions and remaining deployment work.
